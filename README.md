# KantanDakoku（Android / CC-BizMate）— 試作版 v0.3.5

指定された `https://kintai.ccbizmate.biz/` だけを WebView で開き、
ホーム画面の「出勤」「退勤」ショートカットから、ログインと打刻ボタン押下を試みる Android アプリです。

## v0.3.5: 打刻画面のバージョン表示・画面表示モードへの復帰（2026-11-11）

- 出勤・退勤打刻画面のヘッダーをそれぞれ **「出勤打刻処理 v0.3.5」「退勤打刻処理 v0.3.5」** と表示します。実際のインストール済み `versionName` を毎回取得するため、次版でも自動追従します。
- v0.3.4で試験導入した画面非表示のWebViewは、実機で進行しないとの報告があり、**安全のため停止**しました。以前バックグラウンドモードをONにしていても、自動でOFFに戻してWebViewのある通常画面を起動します。
- バックグラウンドサービス・通知権限・ON/OFF設定を取り除きました。打刻ショートカットの起動先・既存認証情報・ボタン登録は維持します。最後の処理結果だけ設定画面に参考情報として残します。
- 勤怠サイトへのクリック操作が成功しても**サーバーの打刻確定は保証できません**。画面に表示される勤怠記録で確認してください。
- 真のバックグラウンド打刻には、勤務先の承認を得た公式API等とサーバー応答の検証が必要です。この版はバックグラウンド処理に対応しません。

## v0.3.4: バックグラウンド打刻（試験的、2026-11-04）

出勤・退勤ショートカットから **画面を開かずに処理を試みる** `BackgroundPunchService` を追加しました。
アプリ側の設定画面に「⑤ バックグラウンド打刻（試験的）」を追加し、手動でONにした場合だけ有効です。
初期値はOFFのため、既存バージョンの画面表示型の打刻はそのまま動きます。

- ON: ショートカットを押すと、専用Activityがサービスを起動して即終了します。Androidのフォアグラウンドサービス（`dataSync`）が端末上で非表示WebViewを使用し、Cookie削除→ログイン→登録済みボタンを最大1回クリックします。
- 処理中は「出勤／退勤 処理中」の通知、処理後は結果通知を表示します。Android 13以上では設定画面から通知権限を要求します。通知が拒否・無効の場合は従来の画面表示型に切り替わります。
- ボタンのクリック試行後、画面遷移または一定の待機後に処理を終了します。**サーバーによる打刻受理を確認する処理はありません**。通知では「送信操作を試みました。打刻記録は未確認」と表示します。
- WebViewを画面非表示で利用する方法は端末・Webサイトによっては正常に動かず、特に可視性判定、位置情報、JS確認ダイアログ、外部認証、認証画面変更に失敗する可能性があります。位置情報・確認ダイアログが必要な場合は自動入力せず中止し、通知から通常のアプリを開いてください。
- 同時実行を抑止し、同じ出勤／退勤の**90秒以内の再クリックを抑止**します。セッションタイムアウトは打刻前なら最大1回だけ再ログインします。打刻試行後は再ログイン・再打刻しません。
- プロセスがOSに終了された場合は自動再送信せず、打刻できたかはサイトの勤怠記録で確認してください。処理タイムアウトは60秒です。勤怠実績の自動入力は今回も対象外です。
- 初回はサイト上の記録と必ず照合し、勤務先の許可を得て利用してください。

### バックグラウンドモードを試す手順

1. ZIPから同一アプリIDの v0.3.4を上書きインストールします。設定と既存ショートカットは保持されます。
2. アプリ本体を開き、設定の「⑤ バックグラウンド打刻（試験的）」のON/OFFを押します。必要に応じて通知を許可してください。
3. 出勤か退勤のホーム画面アイコンをタップします。サイト画面は開かず、処理中の通知が表示されます。
4. 処理終了後の通知を確認し、CC-BizMate上の勤怠記録を照合してください。失敗したら設定をOFFにして通常画面から打刻してください。

**重要:** AndroidのWebViewを画面に貼り付けずに動作させる方式はAndroid実機で未検証です。
このバージョンは技術検証用です。安定運用するには会社公認のAPIまたはログイン・打刻のHTTP仕様と成功レスポンスの正確な検証が必要です。

## v0.3.3: Gradle Wrapper の修復（2026-10-24追補）

- 以前の `setup-gradle-wrapper.ps1` が公式URLで HTTP 404 になる問題を修正しました。
- Gradle公式で公開された **8.13のWrapper JAR SHA-256** と一致する既存ファイルがあれば再利用し、なければGradleの公式GitHubリポジトリに登録されたタグ付きファイルを取得して、公開済みの8.13公式SHA-256と照合します。SleepTraceの未検証JARには依存しません。
- ソースのZIPにはWrapper JARを同梱していません。初回の `gradlew.bat --version` 実行時に `setup-gradle-wrapper.ps1` がSHA-256検証後に取得します。ダウンロードできない場合は停止します。
- Kotlin依存関係の修正は TrafficMap に適用するもので、かんたん打刻のアプリコードや認証情報保存機構は変更していません。

## 対応環境

- Android 8.0 以降（minSdk 26。Android 13 も対象）
- Java のソース（Kotlin不要）
- Android Gradle Plugin 8.11.1 / Gradle 8.13 / JDK 17〜21
- Android SDK Platform 35（Android Studio の SDK Manager から追加可能）

## Windows / Android Studio での起動手順

1. ZIP を解凍する（日本語・空白を含まない短い場所を推奨）。
2. 解凍フォルダーで `gradlew.bat --version` を一度実行する。検証済みJARがなければGradle公式GitHubリポジトリから取得してSHA-256を検証します。Gradle 8.13 本体が未キャッシュの場合はGradle側でダウンロードされます。
3. Android Studio の **Open** から `KantanDakoku-Android` フォルダーを選択する。
4. Gradle JDK は **JBR 21** を選ぶ。Android SDK Platform 35 がない場合はインストールする。
5. Android 端末を USB 接続して Run（▶）でインストールする。APK はこの ZIP に含まれません。
6. 初回起動時に会社ID・アカウント・パスワードを設定して保存する。
7. 「ログイン画面を開く」でサイトの画面を確認する。
8. 「出勤ボタンを登録」でログイン後の実際の**出勤**ボタンをタップ、確認ダイアログで登録する。同様に「退勤ボタンを登録」。学習時の通常の click イベントは阻止しますが、サイト側の特殊な mousedown/touchstart 処理を完全に阻止する保証はありません。学習は勤怠管理者の許可がある環境で行ってください。
9. 「ホーム画面に『出勤』を追加」「ホーム画面に『退勤』を追加」を押し、Android ランチャーで追加を承認する。
10. 以後ホーム画面から該当アイコンを1回押すと、画面表示方式でログインと打刻を試みます。

## v0.3.0 セッションタイムアウト対応

- **出勤・退勤ショートカットの起動時は、WebView に残る Cookie をすべて削除し、必ずログインページから開始**します。以前の版のように保存済みセッションのまま `/C03/C0301Top` を直接開くことはありません。毎回ログインが必要ですが、認証情報の自動入力を試みます。
- サイトから「セッションのタイムアウトが発生しました。ログインページより再度ログインしてください」のような画面が返った場合、表示文字列から検知しログイン画面に戻ります。タイムアウトによる自動再ログインは**1回限り**です。失敗が続く場合は停止します。
- 操作画面に **「ログイン画面へ」** を追加しました。押すと自動クリックを停止したうえで手動ログインできます。
- 打刻ボタンを一度押した**後**にセッションアウトした場合は、打刻済みか判別できないため自動再送しません。管理画面で実際の勤怠記録を確認してください。
- **実際のログアウトURLやサーバーのログアウト処理は呼んでいません**。新しい打刻の前にログインCookieを消去する方式です。学習モードと手動確認モードは初回からCookieを消去せず、タイムアウトを検出した場合にログイン画面へ移動します。

### 更新方法

既存のアプリをアンインストールせず、**同じアプリIDの v0.3.5 を Android Studio から Run で上書きインストール**してください。端末に保存済みの認証情報・ボタン登録は原則維持されます。ホーム画面の「出勤」「退勤」ショートカットも引き続き使用できます。ビルドに失敗する場合は、Gradle Sync、SDK Platform 35、JDK 21 の設定を確認してください。

## 動作・安全上の制約

- **実運用に先立ち勤務先・システム管理者に Web画面の自動操作が許可されているか確認してください。**
- 打刻時刻は CC-BizMate のサーバー上の記録が基準です。アプリを押した時刻との一致は保証しません。
- **「クリック試行」と「打刻登録成功」は異なります。** この試作は打刻成功メッセージの検出・日次記録の照会までは実装していません。必ずサイト上の記録をご確認ください。
- 手動選択で保存した CSS セレクタが変更された場合はクリックを停止します。再登録してください。
- 初回ログインは HTML を自動判定します（可視パスワード欄1つと会社ID/アカウントのテキスト欄2つ）。構造に合わない場合は自動ログインを断念し、手動ログインできます。
- ログインの自動送信は原則1回です。サイト側が明示的にセッションタイムアウトを返した場合に限り、最大1回の再ログインを試行します。通常の認証失敗では繰り返し送信しません。
- 打刻の自動クリックは**1実行につき最大1回**です。ショートカットを連続タップすると複数画面が起動する可能性があるため、打刻結果を確認するまで連打しないでください。
- 打刻画面は必ず表示されます。時刻予約・無人の定期打刻は行いません。
- Android WebView と Chrome は通常別のログイン状態です。Chrome に既にログインしていても WebView では別途ログインが必要です。v0.3 ではショートカットを押すたびにWebView側のログインCookieを消去します。
- 機能の有無や仕様は会社ごとの CC-BizMate 設定により変わります。打刻時に位置情報が必要な場合は端末に許可を求めます。
- Android Keystore（AES-256-GCM）で認証情報を端末内暗号化保存します。バックアップは無効です。保存の可否は勤務先のセキュリティポリシーに従ってください。外部分析・ログ送信機能はありません。
- 無関係な HTTP や別サイトへのページ遷移はアプリ内 WebView で処理せず、外部ブラウザへ送ります。TLS エラー時は処理を停止します。
- 製品公式が用意した API を使用したものではありません。
- 実際のログイン認証・打刻サーバーにアクセスできない環境で作成したため、**動作確認・ビルド確認は未実施**です。端末で画面と結果を確認し、必要なら修正してください。

## v0.3.0: ログイン送信改善と勤務実績画面の参照用解析

- ログインを自動入力後、名前が明確なログイン操作要素を最優先でクリックします。見つからない場合には、認証フォームの唯一の submit コントロールを `requestSubmit` し、さらにボタンがない場合はフォーム自体に `requestSubmit()` を実行します。複数の候補がある場合などは誤送信防止のため停止します。
- **解析モード** (`ANALYZE`) を追加しました。自動ログイン後、自分で勤務実績画面に移動し「画面構造を取得」をタップすると、フィールド名・ID・表示名・ボタン名を取得してコピーできます。**入力された値、Cookie、パスワード、CSRFトークン、画面本文は収集しません**。解析コードはネットワーク送信・フォーム送信・クリックを行いません。
- 解析モードは**画面操作を完全に閲覧専用にロックする機能ではありません**。勤務実績画面の「保存」「登録」「確定」等は押さないでください。
- 勤務実績の自動入力および保存は **まだ実装していません**。実際の勤務実績画面の構造、会社固有の必須項目、ルールを確認してから実装します。
- 自動打刻はv0.2と同じくショートカット起動時に行われます。試験で誤打刻しないように勤務時間帯以外での打刻テストは避けてください。
- ソースコードやZIPに実際の会社ID・ユーザーID・パスワードを含めない設計を継続します。v0.2で保存済みの認証情報は端末にのみ保持します。

## 参照のみで調査する手順

1. 既存v0.2に上書きインストールし、アプリの設定画面で「画面解析モードで開く」をタップする。
2. 自動ログインが成功したら通常メニューから勤務実績の入力画面を**表示するだけ**（保存・登録などは押さない）。
3. アプリ上部の「画面構造を取得（入力値は取得しない）」をタップする。
4. 表示されたレポートに個人情報がないかを確認し、必要部分だけ共有する。
5. 日次実績の入力画面以外にも確認画面やメニュー画面があれば、それぞれ解析する。

- 自動ログインがサイト固有のJavaScript部品で失敗する場合は、設定画面の「ログインボタンを登録」を使用できます。学習中の通常クリックを抑止し、登録した要素を次回の自動ログインから優先して押します。初回の学習画面では認証情報を送信しません。


## v0.3.1: 退勤ショートカットを押しても出勤アイコンが出る問題

- **原因**: v0.3ではピン留めアイコンだけ出勤・退勤で分け、起動先を共通の `MainActivity` にしていました。`AndroidManifest.xml` のアプリ既定アイコンは出勤用だったため、Androidの起動時（スプラッシュ等）に出勤アイコンが見える場合がありました。
- **修正**: 出勤と退勤の専用 Activity `ClockInActivity` と `ClockOutActivity` を追加し、専用アイコン・Android 12+用スプラッシュテーマを指定しました。退勤起動では強制的に `OUT` モードとなります。
- **画面表示**: WebView画面の上部にも「出勤打刻処理」「退勤打刻処理」と、それぞれのアイコンを明示しました。
- **ショートカットの更新**: メインのアプリを一度開くと、既存の `punch_IN` / `punch_OUT` ショートカットに新しい起動先とアイコンの更新を試みます。ホームアプリが古い表示を保持する場合は、ホーム画面の旧「退勤」を削除したうえで、アプリ内の「ホーム画面に『退勤』を追加」を使って作り直してください。
- **打刻処理**: WebView のログイン・クリック判定は v0.3 から変更していません。表示アイコンだけを取り違えていた可能性が高く、実打刻の結果はCC-BizMateの勤怠記録でご確認ください。
- **保存データ**: アプリIDは従来と同じで、認証情報と登録済みボタンの選択情報を引き継ぐ構成です。社員の認証情報をソース・ZIPに埋め込んでいません。
- **検証**: ソース上のリンク・リソース構造とモードの対応は検査しています。Android SDK／実機がないためAPKビルド・端末実行は未検証です。
